## 1. Summary — top 12 priorities

The scheduling core is in decent shape (worker thread, master/sub precedence, frozen zone, CTP, changeovers). The biggest risks sit **around** it: an unauthenticated endpoint that can repoint or reconfigure the app, a SYSPRO write-back that overwrites job due dates, silent auth breakage, and N+1 data loading that will not scale past a demo DB.

## 2. Architecture as found

```
Browser (React 18 + Vite, zustand)          CP-SAT sidecar (FastAPI + OR-Tools, optional)
   │  axios (api.ts) + raw fetch() in 7 files        ▲ HTTP :5050
   ▼                                                 │
Express API :3000 (serves /api + frontend/build) ────┘
   ├─ worker_threads → SchedulingEngine (greedy) / CpSatEngine
   ├─ app.locals + sch_AppState  (pins, shifts, resource defs, imported jobs)
   ├─ SCHEDULER DB (dbo.lic_*, sch_*)            ← auth, licences, settings, matrices
   └─ SYSPRO company DB
        ├─ reads: WipMaster, WipJobAllLab, WipJobAllMat, BomMachine, BomWorkCentre, InvMaster, InvWarehouse, PorMasterDetail
        ├─ aps.SavedSchedules / aps.Scenarios    ← scheduler-owned, but living inside SYSPRO
        ├─ aps.* LYNQ-compat tables, views, procs (create_aps_lynq_compat_objects.sql)
        └─ writes on export: aps procs + direct UPDATE WipJobAllLab / WipMaster
```

Structural observations:

- **State is split across 3 stores.** Saved schedules live in the SYSPRO DB (`aps.SavedSchedules`). Settings and matrices live in the SCHEDULER DB. Pins, shifts and resource definitions live in `app.locals` + a JSON blob (`sch_AppState`). None of the `sch_AppState` data is keyed by company, so switching company via `/connect` keeps the previous company's pins, shifts and machine definitions.
- **Two role vocabularies.** Local users are `super_admin / company_admin / planner / viewer`. NTLM users get `Reviewer`, and scenarios check for `Approver`. NTLM users also always have `companyId: null`, so company settings (rule toggles, include-completed-ops) never apply to them.
- **`App.tsx` is 3 546 lines** with 19 `useState` and 19 `useEffect`. Beyond it: 24 content tabs, 8 ribbon tabs and a 1 472-line Gantt.

## 3. Fix — bugs, correctness and security

### 3.1 Security

1. **Lock down setup routes** (`app.ts:101-105`). Allow `/status/databases` and `/status/connect` without a JWT **only** while no scheduler DB is configured (first-run). After that, require `super_admin`. Also bind first-run to `127.0.0.1` requests only.
2. **Stop writing passwords to `.env` from the API** (`status.ts:persistConnectionProfile`). At minimum, never write them when the request didn't come from localhost. Better: use Windows auth or DPAPI-encrypted secrets.
3. **Remove secret fallbacks.** Add `JWT_SECRET` to `requireEnv()` in `config/database.ts` (or a new `config/secrets.ts`). Import it once instead of redefining it in 3 files.
4. **Default admin.** Generate a random first-run password, print it once to the console, and add a `must_change_password` flag to `lic_users`.
5. **User management scoping** (`users.ts`). On `GET/PUT/DELETE /:id`, load the target and reject if `target.company_id !== req.user.companyId` (unless the caller is `super_admin`). Reject `role: 'super_admin'` unless the caller is `super_admin`.
6. **Role guards on writes.** Today any authenticated user, including `viewer`, can generate/save/load-version, edit the setup matrix, shifts, resource definitions and pins, bulk-import jobs, and approve overrides. Add `requireRole('super_admin','company_admin','planner')` to every mutating route.
7. **Export must read from the DB, not the request body** (`schedule.ts:1594`). Load `ScheduleData` by `scheduleId`, require `Status = 'Approved'`, then export. This also removes the 10 MB JSON limit risk.
8. **Refresh tokens** are stored in plaintext in `lic_sessions`. Store a SHA-256 of the token instead. Also tighten `cors()` to the app's own origin, since same-origin serving makes CORS unnecessary.
9. **SSE and shop-floor are public** (`/api/schedule/events`, `/api/shopfloor/*`). Shop-floor exposes job and op data to anyone on the LAN. Use a short-lived query-string token or a cookie.
10. **`approve-override` audit actor** is always `anonymous`: it reads `user.userId`, but the field is `sub` (`schedule.ts:1685`).

### 3.2 SYSPRO write-back (export)

1. **Don't touch `JobDeliveryDate` or `JobStartDate`** (`APSDatabaseService.ts:~600-605`). Write only the `Sch*` fields. The due date is the customer promise and the scheduler's own tardiness input.
2. **Direct `UPDATE`s to `WipMaster` / `WipJobAllLab` bypass SYSPRO business logic** and can hold row locks on core WIP tables for the whole export transaction (row-by-row, after a cache refresh). Options, best first:
   - Post through **e.net business objects**. You already have an XML generator for `WIPTJL` labour allocations (`GenerateLabourAllocationsWIPTJLXML_DELETE.sql`), and the same pattern works for job header dates.
   - Or keep direct SQL, but make it **one set-based `UPDATE ... FROM OPENJSON(@ops)`** per table instead of N statements (sample in §6.4).
3. **`TRY_CONVERT(int, Operation) = @sequence`** forces a scan of `WipJobAllLab` for every op. Compare `Operation = @sequence` directly (the column is numeric) so the PK seek is used.
4. **Imported (non-SYSPRO) jobs abort the whole export.** `No WipMaster row updated` throws and rolls everything back. Skip jobs flagged as imported, and report them.
5. **Idempotency.** Every export calls `Lynq_VP_BPL_CreateWIBPL` per job. A client timeout (axios default 30 s, see 3.4) followed by a retry can create duplicate BPL orders. Add an export-run id and skip jobs already written for that schedule id.
6. `cleanupClosedOperations(1)` runs on every export. Move it to a daily job.

### 3.3 Frontend bugs

1. **Hardcoded API base.** Delete the local `API`/`API_BASE_URL` constants and import one `API_BASE_URL` from `services/api.ts` (it already falls back to `window.location.origin`). Files: `AuthContext.tsx:4`, `LicenseAdmin.tsx:5`, `ScenariosPanel.tsx:11`, `SettingsPanel.tsx:8`, `UserManagement.tsx:5`, `useSseEvents.ts:3`, `bulkImportService.ts:9`. `App.tsx:58` is declared but unused — delete it.
2. **Scenarios auth.** Replace the raw `fetch` + `localStorage.aps_token` with `apiClient` (which injects the token). Change the backend guard to `requireRole('super_admin','company_admin','planner')`.
3. **401 handling** (`AuthContext.tsx:147`). Read the token through a ref, and on 401 attempt one `refreshSession()` + request retry before logging out. The 7-hour `setInterval` refresh is unreliable across laptop sleep. Refresh on `visibilitychange` / focus when the token is within 30 min of expiry.
4. **Export timeout.** `exportToSyspro` uses the 30 s default. Give it `{ timeout: 300000 }` like generate, and disable the button while it runs.
5. **Fake progress bar** (`App.tsx:772-795`): progress is time-estimated, not real. Either label it “working…” with a spinner, or have the worker post real progress (`parentPort.postMessage({progress})`) and stream it over SSE.
6. `index.html` still has `theme-color #667eea` (the removed purple). Use `#4f8bff`.
7. Blocking `window.confirm` / `alert` in 5 places (`AppRibbon.tsx:222`, `ConstraintOverrideModal.tsx:26`, `ScenariosPanel.tsx:131,154`, `ShiftManagementTab.tsx:216`). Replace them with the app's modal pattern.

### 3.4 Backend bugs

1. **SSE query** — replace with the fixed SQL in §6.2. Also run **one** shared poller for all clients (module-level interval + a `Set` of responses), not one per connection.
2. **Lost warnings** — schedule-order material refinement pushes to `schedule.violations`, but the engine, UI and counts use `constraintViolations` (`schedule.ts:414-419`). Those warnings never reach the UI.
3. **`executionTimeMs: Date.now()`** returns an epoch timestamp, not a duration (`schedule.ts:471`).
4. **Non-atomic save.** `UPDATE IsLatest=0` → `DELETE` → `INSERT` run as 3 separate statements in `/generate`, `/save` and `/load-version`. A failure between them leaves **no** latest schedule. Wrap each in `withTransaction`.
5. **Worker has no timeout.** A hung engine run hangs the HTTP request forever. Add `setTimeout(() => worker.terminate(), N)`. Also extract the duplicated worker-spawn code (`/generate` and `/optimize`) into one helper.
6. **Migration runner** splits on `/\bGO\b/i`, so a comment like `-- go live` breaks a migration. Split on `^\s*GO\s*$` (multiline), and run each migration in a transaction.

### 3.5 Scheduling-engine correctness

1. **Overtime bucketed by UTC day** — `slot.capacityStart.toISOString().slice(0,10)` (`SchedulingEngine.ts:1141, 1413, 1584` — three places). In Brisbane (UTC+10), anything before 10:00 counts against the previous day. Use a local `yyyy-MM-dd`.
2. **“Resource utilization” isn't utilization.** It is `regular / (regular + overtime)` ≈ 100 % almost always (`calculateMetrics`). Use booked hours ÷ available calendar hours in the horizon. The Optimizer ranks rules on this metric, so its ranking is skewed.
3. **Holidays are ignored.** `calendar.holidays` is populated but never read in `getProductiveWindowsForDay`, and `CtpService` mirrors the same gap. Public holidays get scheduled.
4. **Sequence-dependent setup uses the wrong predecessor.** `lastItemPerResource` is the last item *placed* in job order, not the item that precedes the slot *in time*. When an op back-fills an earlier gap, the changeover is charged against the wrong item. Since the workcentre is the unit of capacity (capacity = 1), track the predecessor per **workcentre** by looking up the slot immediately before `candidateStart`.
5. **Silent iteration cap.** `MAX_SLOT_ITERATIONS = 1500` breaks out and leaves the op unscheduled without a specific reason. Emit an “search limit reached” violation so the Unscheduled list explains it.
6. **O(n²) slot search.** Each probe filters every slot on the resource and workcentre, and each placement re-sorts the whole list. Keep slots sorted and binary-search the insertion point / first overlap. This matters once you pass a few thousand ops.
7. `totalJobsScheduled` counts unscheduled jobs too. Use `scheduledJobs.length`.

### 3.6 Material availability logic

1. **Column names** — see §6.1 diagnostic. If `QtyAllocWip` / `QtyAllocSO` don't exist on your install, WIP and SO allocations are treated as 0 → shortages are under-reported.
2. **Issued material is counted as still required.** `requiredQty = unitQty × QtyToMake × (1+scrap)` ignores `QtyIssued` on `WipJobAllMat`. Partly-kitted jobs show false shortages.
3. **The job's own allocation is subtracted from its own availability.** Warehouse-level WIP allocation already includes this job's reservation. Correct formula: `free = OnHand − (AllocWip − thisJobOutstanding) − AllocSO`.
4. **Warehouse is ignored.** Stock is summed across all warehouses, but `WipJobAllMat` lines carry a warehouse. Stock in a remote warehouse makes a job look kitted.
5. **Need date** = min(release, due). Once scheduled, use the op's planned start (the refinement pass already has it).
6. **Silent BEGIN CATCH.** The `BEGIN CATCH → SELECT TOP 0` blocks turn any SQL error into “no BOM lines” → status **Materials / OK**. A failed query should surface as a warning, not a green light.
7. **`WipJobAllocation`** is not a standard SYSPRO table as far as I know. Confirm with §6.1; if it's absent, the fallback branch (no `QtyIssued`) is what runs.

### 6.1 Diagnostic — confirm the column names the material plan relies on (SYSPRO company DB, read-only)

```sql
-- Which allocation columns exist? (material plan expects QtyAllocWip/QtyAllocSO; inventory.ts uses QtyAllocatedWip/QtyAllocated)
SELECT t.name AS TableName, c.name AS ColumnName
FROM sys.columns c
JOIN sys.tables  t ON t.object_id = c.object_id
WHERE (t.name = 'InvWarehouse' AND c.name LIKE 'QtyAlloc%')
   OR (t.name = 'WipJobAllMat' AND c.name IN ('UnitQtyReqd','NetUnitQtyReqd','QtyIssued','Warehouse','FixedQtyPerFlag'))
   OR (t.name = 'WipMaster'    AND c.name IN ('Status','HoldFlag','ConfirmedFlag','TimeStamp'))
   OR (t.name = 'WipJobAllLab' AND c.name IN ('TimeStamp','OperationStatus','ScheduledMachine'))
ORDER BY t.name, c.name;

-- Which optional tables exist on this install?
SELECT v.name,
       CASE WHEN OBJECT_ID(v.name, 'U') IS NULL THEN 'missing' ELSE 'present' END AS state
FROM (VALUES ('WipJobAllocation'),('WipJobAllMat'),('WipMasterSub'),('WipSubJob'),
             ('BomMachine'),('BomWorkCentre'),('BomWorkCentres'),('aps.SavedSchedules')) v(name);

-- How big is the saved-schedule history inside SYSPRO?
IF OBJECT_ID('aps.SavedSchedules','U') IS NOT NULL
```

### 6.2 Fixed SSE change-detector query (replace `events.ts:getWipSnapshot`)

It uses only columns the app already reads, with no nested aggregates, and covers op-level changes (completions and bookings) too.

```sql
SELECT
  (SELECT COUNT(*) FROM WipMaster WHERE ISNULL(Complete,'N') <> 'Y') AS jobCount,
  (SELECT CHECKSUM_AGG(CHECKSUM(Job, HoldFlag, ConfirmedFlag, JobDeliveryDate, QtyToMake))
     FROM WipMaster WHERE ISNULL(Complete,'N') <> 'Y') AS jobChk,
  (SELECT CHECKSUM_AGG(CHECKSUM(l.Job, l.Operation, l.OperationStatus, l.IExpUnitRunTim))
     FROM WipJobAllLab l JOIN WipMaster wm ON wm.Job = l.Job
     WHERE ISNULL(wm.Complete,'N') <> 'Y') AS opChk;
```

If §6.1 shows a `TimeStamp` (rowversion) column on `WipMaster` / `WipJobAllLab`, `SELECT MAX(TimeStamp)` is cheaper still.

### 6.3 Set-based loaders to replace the N+1 queries (SYSPRO company DB, read-only)

**All operations for all open jobs — one query** (replaces the per-job `getOperationsByJob` loop). Group by `jobId` in TS.

```sql
SELECT
  l.Job                                   AS jobId,
  CAST(l.Operation AS int)                AS sequence,
  CONCAT(l.Job, '-OP', CAST(CAST(l.Operation AS int) AS varchar(20))) AS opId,
  ISNULL(l.WorkCentre, ISNULL(l.IMachine, 'WC-UNKNOWN')) AS workcentreId,
  ISNULL(l.IExpUnitRunTim,0) * ISNULL(NULLIF(l.ParentQtyPlanned,0), ISNULL(wm.QtyToMake,1)) AS duration,
  ISNULL(l.IExpSetUpTime,0)               AS setupTime,
  ISNULL(l.QueueTime,0)                   AS queueTime,
  ISNULL(l.MovementTime,0)                AS moveTime,
  ISNULL(NULLIF(l.IQuantity,0),1)         AS batchSize,
  ISNULL(NULLIF(LTRIM(RTRIM(l.OperationStatus)),''),'NotStarted') AS status,
  l.ScheduledMachine, l.IMachine
FROM WipJobAllLab l
JOIN WipMaster   wm ON wm.Job = l.Job
WHERE ISNULL(wm.Complete,'N') <> 'Y'
ORDER BY l.Job, l.Operation;
```

**All outstanding material for all open jobs — one query** (replaces the per-job `getMaterialsByJob` loop). It nets off issued quantity and keeps the warehouse. Confirm `QtyIssued` / `Warehouse` with §6.1 first.

```sql
SELECT
  m.Job                         AS jobId,
  m.StockCode                   AS componentCode,
  m.Warehouse                   AS warehouse,
  SUM(ISNULL(NULLIF(m.NetUnitQtyReqd,0), ISNULL(m.UnitQtyReqd,0)) * ISNULL(wm.QtyToMake,1)) AS requiredQty,
  SUM(ISNULL(m.QtyIssued,0))    AS issuedQty,
  SUM(ISNULL(NULLIF(m.NetUnitQtyReqd,0), ISNULL(m.UnitQtyReqd,0)) * ISNULL(wm.QtyToMake,1)
      - ISNULL(m.QtyIssued,0))  AS outstandingQty
FROM WipJobAllMat m
JOIN WipMaster wm ON wm.Job = m.Job
WHERE ISNULL(wm.Complete,'N') <> 'Y'
  AND ISNULL(m.StockCode,'') <> ''
GROUP BY m.Job, m.StockCode, m.Warehouse
HAVING SUM(ISNULL(NULLIF(m.NetUnitQtyReqd,0), ISNULL(m.UnitQtyReqd,0)) * ISNULL(wm.QtyToMake,1)
           - ISNULL(m.QtyIssued,0)) > 0;
```

**Stock only for components in play** (replaces the full `InvMaster` + `InvWarehouse` scans; per warehouse).

```sql
;WITH need AS (
  SELECT DISTINCT m.StockCode, m.Warehouse
  FROM WipJobAllMat m JOIN WipMaster wm ON wm.Job = m.Job
  WHERE ISNULL(wm.Complete,'N') <> 'Y' AND ISNULL(m.StockCode,'') <> ''
)
SELECT w.StockCode, w.Warehouse, w.QtyOnHand, w.QtyAllocated, w.QtyAllocatedWip
FROM InvWarehouse w
JOIN need n ON n.StockCode = w.StockCode AND n.Warehouse = w.Warehouse;
```

Expected effect: a generate on ~1 000 jobs goes from ~3 000 round-trips to 5–6. Also call the material plan **once** and reuse it for the schedule-order refinement (only the ordering differs).

### 6.4 Set-based write-back (only if you keep direct SQL rather than business objects)

One statement per table instead of one per op. Pass the ops as JSON from TS (`@ops` = `[{job, op, machine, sd, st, ed, et, rsd, rst}]`, with dates/times already converted to SYSPRO formats). It deliberately does **not** touch `JobDeliveryDate` / `JobStartDate`.

```sql
-- @ops nvarchar(max) supplied by the app
UPDATE l SET
  l.ScheduledMachine = o.machine,
  l.SchStartDate     = o.sd,  l.SchStartTime    = o.st,
  l.SchEndDate       = o.ed,  l.SchEndTime      = o.et,
  l.SchStartRunDate  = o.rsd, l.SchStartRunTime = o.rst
FROM WipJobAllLab l
JOIN OPENJSON(@ops) WITH (
  job varchar(20) '$.job', op decimal(9,2) '$.op', machine varchar(20) '$.machine',
  sd datetime '$.sd', st decimal(9,0) '$.st', ed datetime '$.ed', et decimal(9,0) '$.et',
  rsd datetime '$.rsd', rst decimal(9,0) '$.rst'
) o ON l.Job = o.job AND l.Operation = o.op;   -- direct compare → PK seek, no TRY_CONVERT
SELECT @@ROWCOUNT AS rowsAffected;
```

Match `st` / `et` types to what `toSysproTimeValue()` returns today. Also stop overwriting `IMachine` (the routing's machine) — `ScheduledMachine` is the scheduled one.

### 6.5 Housekeeping scripts

**Retention for `aps.SavedSchedules`** (SYSPRO company DB). Every generate inserts a full JSON copy. This keeps the latest, all Approved versions, and the newest 30 drafts.

```sql
;WITH ranked AS (
  SELECT ScheduleID, IsLatest, Status,
         ROW_NUMBER() OVER (ORDER BY SavedAt DESC) AS rn
  FROM aps.SavedSchedules
)
DELETE s
FROM aps.SavedSchedules s
JOIN ranked r ON r.ScheduleID = s.ScheduleID
WHERE r.IsLatest = 0 AND r.Status <> 'Approved' AND r.rn > 30;
SELECT @@ROWCOUNT AS VersionsDeleted;
```

**Only one latest row, enforced by the DB** (SYSPRO company DB). It makes the non-atomic save bug (§3.4-4) fail loudly instead of silently.

```sql
UPDATE aps.SavedSchedules SET IsLatest = 0
WHERE IsLatest = 1
  AND ScheduleID <> (SELECT TOP 1 ScheduleID FROM aps.SavedSchedules WHERE IsLatest = 1 ORDER BY SavedAt DESC);
IF NOT EXISTS (SELECT 1 FROM sys.indexes WHERE name = 'UX_aps_SavedSchedules_OneLatest')
  CREATE UNIQUE INDEX UX_aps_SavedSchedules_OneLatest ON aps.SavedSchedules (IsLatest) WHERE IsLatest = 1;
```

**Drop the duplicate index** (SCHEDULER DB).

```sql
IF EXISTS (SELECT 1 FROM sys.indexes WHERE name = 'IX_sch_ClassChangeover_From' AND object_id = OBJECT_ID('dbo.sch_ClassChangeover'))
  DROP INDEX IX_sch_ClassChangeover_From ON dbo.sch_ClassChangeover;
```

### 6.6 Least-privilege logins (replaces `sa`)

Run on the SQL instance as sysadmin. Set the two passwords on the first lines, and change `USE HFARMCompany1` if your company DB differs. Scheduler login: full rights on SCHEDULER. SYSPRO login: read on `dbo`, full rights only on the `aps` schema, and UPDATE only on the columns the export writes.

```sql
DECLARE @schedPwd nvarchar(128) = N'SetAStrongPassword1!';
DECLARE @sysproPwd nvarchar(128) = N'SetAStrongPassword2!';
IF SUSER_ID('aps_scheduler') IS NULL EXEC('CREATE LOGIN aps_scheduler WITH PASSWORD = ''' + @schedPwd + ''', CHECK_POLICY = ON');
IF SUSER_ID('aps_syspro')    IS NULL EXEC('CREATE LOGIN aps_syspro    WITH PASSWORD = ''' + @sysproPwd + ''', CHECK_POLICY = ON');
GO
USE SCHEDULER;
IF USER_ID('aps_scheduler') IS NULL CREATE USER aps_scheduler FOR LOGIN aps_scheduler;
ALTER ROLE db_datareader ADD MEMBER aps_scheduler;
ALTER ROLE db_datawriter ADD MEMBER aps_scheduler;
ALTER ROLE db_ddladmin   ADD MEMBER aps_scheduler;   -- migrations
GO
USE HFARMCompany1;   -- your SYSPRO company DB
IF USER_ID('aps_syspro') IS NULL CREATE USER aps_syspro FOR LOGIN aps_syspro;
ALTER ROLE db_datareader ADD MEMBER aps_syspro;
GRANT SELECT, INSERT, UPDATE, DELETE, EXECUTE ON SCHEMA::aps TO aps_syspro;
GRANT UPDATE ON dbo.WipJobAllLab (ScheduledMachine, SchStartDate, SchStartTime, SchEndDate, SchEndTime, SchStartRunDate, SchStartRunTime) TO aps_syspro;
GRANT UPDATE ON dbo.WipMaster    (SchStartDate, SchStartTime, SchEndDate, SchEndTime, ScheduleFlag, DateCalcMethod) TO aps_syspro;
GO
```

Then set `SYSPRO_DB_USER=aps_syspro` and `SCHEDULER_DB_USER=aps_scheduler` in `backend/.env`. `ensureSysproObjects` needs `CREATE TABLE` in `aps` once. Run it as `sa` on first install, or grant `ALTER ON SCHEMA::aps` + `CREATE TABLE` to `aps_syspro`.

### 6.7 Structural recommendation

Move `aps.SavedSchedules` and `aps.Scenarios` **out of the SYSPRO company DB** into the SCHEDULER DB, adding a `CompanyDb` column. SYSPRO upgrades, restores and company copies then never touch scheduler data, SYSPRO backups stop growing with JSON blobs, and the SYSPRO login can be read-only apart from the export. Keep only the LYNQ-compat `aps.*` objects in SYSPRO, and only if you still need LYNQ compatibility.

## 7. UI and UX

**Information architecture**

1. **24 content tabs + 8 ribbon tabs is too many.** Suggested grouping:
   - **Plan:** Gantt, Job Tree, Dispatch
   - **Analyse:** KPI + Capacity + Bottleneck + Leveling merged into one “Load & KPIs” page
   - **Materials:** Materials, Inventory, BOM tree, Pegging
   - **What-if:** Scenarios, What-if, Optimizer, Compare
   - **Promise:** CTP
   - **Setup:** Changeovers, Shifts, Machines, Settings

   Drop `draggable`, and merge `constraints` with `constraints-mgmt`.
2. **Ribbon labels.** FILE / HOME / REVIEW / VIEW / WORKFLOW overlap (Refresh appears in 3 tabs; “Production Jobs” in REPORTS and VIEW). Put the primary actions in one permanent toolbar: **Week ▸ Rule ▸ Generate ▸ Approve ▸ Send to SYSPRO**, with a status chip (Draft / Approved / Exported + timestamp).
3. **Make the workflow state visible.** “Send to Syspro” should be disabled until the schedule is Approved, and show what will change (N jobs, M ops, first/last date) in a confirm dialog before writing.

**Gantt**

4. **No virtualization** in `MachineGanttBoard` (1 472 lines): every bar renders. Window rows and only render bars inside the visible time range. Needed past a few hundred ops.
5. Show **why** an op sits where it does in the tooltip: waiting on predecessor / material / capacity / pin / frozen zone. Draw late jobs' bars with a red due-date marker.
6. Add a **“today” line**, frozen-zone shading, and non-working-time shading from the real calendar.

**Readability and consistency**

7. Font sizes: 31 rules at 12 px, 22 at 11 px, 7 at 10 px. On a shop-floor screen or projector that's too small. Set a 13 px floor for data and 12 px only for secondary labels.
8. **694 hardcoded hex colours** (245 in `App.css`, 449 in component CSS), 21 `!important`, and 157 inline `style={{}}`. Finish the token migration per `CLAUDE.md` so light mode stops breaking piecemeal.
9. Emoji and glyph icons (`✓ ⚙ 📅 ⚠`, 30 places) sit next to `lucide-react` icons. Standardise on lucide.
10. **Only 6 `@media` rules.** The Shop-floor view is described as mobile-first — test it at tablet width (768 px) and give it large touch targets.
11. **Empty and error states.** When the DB is disconnected, most panels show blank grids. Show one banner with a “Open Company” action instead.

**Accessibility**

12. 196 aria/role attributes is a start, but custom tables (22 `<table>`s) and the Gantt need keyboard navigation and focus styles. Colour-only status in Gantt bars needs a pattern or icon for colour-blind users.
