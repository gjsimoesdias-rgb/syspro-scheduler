## 3. Status of the 29 Sep review

Most of it is done and verified in code: setup routes gated, one JWT secret, hashed refresh tokens, company-scoped user admin, role guards on every mutating route, no `JobDeliveryDate` overwrite, set-based loaders, fixed SSE query plus a shared poller, atomic saves, worker timeout, local-day overtime, holidays/calendar exceptions in both the engine and CTP, least-privilege logins (`aps_syspro` / `aps_scheduler` are in use), plan data moved to the SCHEDULER DB.

**Still open:**

- §3.1-8 `cors()` is still wide open. It isn't needed for same-origin serving.
- §3.1-9 `/api/shopfloor/*` is still public (job and op ids for anyone on the LAN). SSE is public by design and carries no data.
- §3.2-2/3/5 Export: per-row `UPDATE`s, `TRY_CONVERT` scan, no idempotency (see #6, #11).
- §3.2-4 Imported jobs abort the export (#10).
- §3.2-6 `cleanupClosedOperations(1)` still runs on every export.
- §3.3-7 / §7 Blocking `window.confirm` / `alert`: 13 places now, including the new Versions and Markers screens.
- §5.1-8 Typing: 890 lint warnings, mostly `any`.
- Pushing: see §1.

## 4. Recommended fixes, in order

1. **Push now**, then fix the 3 lint errors so CI goes green.
2. **Set `NODE_ENV=production`** in `backend/.env` (or in `START_SCHEDULER.cmd` before `npm start`). One line; it restores rate limiting and stops stack traces leaking.
3. **Exclude / Pin job:** apply `excludedJobIds` in `generateHandler` (filter before `completeJobFamilies`, warning when a family member is excluded). Turn `pinnedJobIds` into op pins built from the latest master (the same code path as the time-fence lock), or remove the menu items. Persist both via `setLocal`.
4. **Optimistic concurrency on the master.** Send the `ScheduleID` and `SavedAt` the board was loaded from. In `saveAsLatest`, reject with 409 when the current latest row differs, and show *"The master changed since you opened it — reload or save as a what-if"*. Do the same check at the start of export.
5. **Make approval real, or drop the pretence.** Either split *Approve* (a role such as `company_admin`/`Approver`, audit-logged with who and when) from *Send*, or call it *Publish* and remove the Approved status check. Enforce `IsLatest = 1 AND VersionKind = 'Plan'` on approve and export, and take an app-level lock (or `sp_getapplock`) around export.
6. **Auto plan:** on commit, give the committed row a new id (or have `runNow` create a fresh what-if when the existing `whatif-auto-plan` row isn't `WhatIf`). Add a test.
7. **`load-version`:** route it through `revertToVersion` (status → Draft, refuses what-ifs), or delete it now that Versions replaces it.
8. **Company settings for null-company users:** resolve the company from the connected SYSPRO DB (one `lic_companies` row per company DB), not only from the user, so super_admin, NTLM users and Auto plan all get the same rules. Also fix NTLM `sub` handling in user settings (key settings by username, or map NTLM users to a `lic_users` row).
9. **Export hardening:** skip non-SYSPRO (imported) jobs, as is already done for `MRP-` jobs; stop writing `IMachine`; compare `Operation = @sequence`.
10. **Company-scope `sch_AppState`** (key `(CompanyDb, StateKey)`) before a second company goes live.

Items 2, 3 and 6 are small (under an hour each). Item 4 is the most important one for a multi-planner site.

> **Data note (corrected):** before `c8d9c82`, exports also wrote the scheduled machine into `WipJobAllLab.IMachine`. >
> **Known limitation:** an op with blank `IMachine` and blank `ScheduledMachine` can go to any machine of its work centre. After it is sent, `ScheduledMachine` holds that machine and later runs keep it there. Use pins or alternatives if that matters.

## 5. What's in good shape

- Clear module boundaries now: `planStore`/`ScheduleStore` for persistence, `publishStatus` as pure functions, `autoScheduler` with a pure `decideAutoRun`, and the pegging, projection and FMAD code as pure tested services. These are easy to test, and most have tests.
- Plan data moved out of SYSPRO with a one-time copy and no destructive migration.
- Export is transactional, incremental (fingerprint per job) and reports per-job errors.
- The engine explains *why* an op waits (line / crew / calendar, blocking jobs). That's a real APS differentiator.
- `App.tsx` went from 3.65k to 1.85k lines, with hooks and panels extracted.

*Not verified: runtime behaviour against a live SYSPRO (no server was started), CP-SAT model internals, MRP suggested-job SQL against other SYSPRO versions, and the new frontend panels' visual behaviour.*
