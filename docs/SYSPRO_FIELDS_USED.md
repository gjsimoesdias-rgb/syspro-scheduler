# SYSPRO / database fields used by the Scheduler

_Generated by auditing the backend query layer. Lists every database field the scheduler
reads, so you can verify the source tables/columns exist in your SYSPRO company database
(names can vary by SYSPRO version)._

## Where this comes from (how to check yourself)

All SYSPRO reads are centralized in the backend:

- `backend/src/database/queries/sysproDashboard.sql` — the main named query set (`SYSPRO_QUERIES`).
- `backend/src/services/SysproDatabaseService.ts` — runs those queries plus a few inline
  queries against the custom `aps.VP_Source*` views (with a fallback to the raw tables).
- `backend/src/api/routes/inventory.ts`, `shopfloor.ts`, `jobs.ts`, `resources.ts` — a few
  route-level queries (inventory, purchase orders, allocations).

Quick re-audit (run in `backend/`):

```
grep -rhoiE '\b(FROM|JOIN)\s+[A-Za-z0-9_.]+' src | sort -u          # tables
grep -rEn '\b[a-z]{1,4}\.[A-Z][A-Za-z0-9_]+' src/database src/services  # aliased columns
```

> The job/operation queries also use `SELECT wm.*` / `SELECT l.*`, so the full row is
> returned at runtime. The fields below are the ones the code actually **maps and depends
> on** — those must exist for the app to work.

## 1. Standard SYSPRO ERP tables

### WipMaster (work orders / jobs) — 14 fields
`Job`, `StockCode`, `JobDescription`, `StockDescription`, `QtyToMake`, `JobDeliveryDate`,
`JobStartDate`, `SchStartDate`, `SchEndDate`, `Priority`, `Complete`, `HoldFlag`,
`ConfirmedFlag`, `ExpMaterial`

### WipJobAllLab (job routing / operations) — 12 fields
`Job`, `Operation`, `WorkCentre`, `WorkCentreDesc`, `IMachine`, `ScheduledMachine`,
`IExpUnitRunTim` (run time), `IExpSetUpTime` (setup), `QueueTime`, `MovementTime`,
`IQuantity` (batch), `OperationStatus`

### WipJobAllMat (job material allocations) — 9 fields
`Job`, `StockCode`, `StockDescription`, `Warehouse`, `Uom`, `QtyTotRequired`, `QtyIssued`,
`QtyOutstanding`, `AllocCompleted`

### InvMaster (stock master) — 7 fields
`StockCode`, `Description`, `StockUom`, `ProductClass`, `AbcClass`, `LeadTime`, `Supplier`

### InvWarehouse (stock by warehouse) — 16 fields
`StockCode`, `Warehouse`, `QtyOnHand`, `QtyAllocated`, `QtyAllocatedWip`, `QtyOnOrder`,
`QtyInInspection`, `QtyInTransit`, `MinimumQty`, `MaximumQty`, `SafetyStockQty`,
`ReOrderQty`, `UnitCost`, `DateLastPurchase`, `DateLastSale`, `DateLastStockMove`

### PorMasterHdr (purchase order headers) — 6 fields
`PurchaseOrder`, `Supplier`, `Warehouse`, `OrderEntryDate`, `OrderDueDate`, `OrderStatus`

### PorMasterDetail (purchase order lines) — 12 fields
`PurchaseOrder`, `Line`, `LineType`, `MStockCode`, `MStockDes`, `MWarehouse`, `MOrderQty`,
`MReceivedQty`, `MOrderUom`, `MPrice`, `MLatestDueDate`, `MCompleteFlag`

## 2. Custom APS views (`aps.VP_Source*`)

Preferred source for jobs/operations; code falls back to raw `WipMaster` / `WipJobAllLab`
if the views aren't present.

### aps.VP_SourceProductionOrdersView — 10 fields
`ProductionOrderNumber`, `ItemNumber`, `Description`, `QuantityOrdered`, `DueDate`,
`ReleaseDate`, `Priority`, `Status`, `CancelledFlag`, `EstimatedMaterialCost`

### aps.VP_SourceProductionOperationsView — 13 fields
`ProductionOrderNumber`, `ProductionOperationNumber`, `SequenceNumber`, `WorkCentreCode`,
`WorkCentreName`, `PrimaryResource`, `AlternateResource`, `EstimatedRunTime`,
`EstimatedSetUpTime`, `QueueTime`, `MovementTime`, `BatchSize`, `OperationStatus`

| SY_ResourceWorkcentre | `ResourceId`, `WorkCentreCode` |
| SY_WorkcentreCapability | `WorkCentreCode`, `Capability` |

## 4. Scheduler-owned tables (not SYSPRO)

The app also creates/reads its own tables (auth, audit, scenarios, settings, AD users,
column profiles, line groups) via `backend/src/database/migrations/`. These aren't SYSPRO
source data, so they aren't detailed here.
